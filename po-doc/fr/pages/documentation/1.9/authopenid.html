OpenID

Authentification Utilisateurs Mot-de-passe
✔ ✔

Le protocole OpenID est obsolète. Il faut maintenant utiliser OpenID-Connect.

Présentation

LL::NG peut deleguer l'authentification à un serveur OpenID. Ceci requiert le module client OpenID pour Perl, version au moins supérieure ou égale à 1.0.

LL::NG peut également agir en serveur OpenID, ce qui permet également d'interconnecter deux systèmes LL::NG.

LL::NG affiche alors un formulaire dans lequel les utilisateurs peuvent entrer leur identifiant OpenID.

L'authentification OpenID peut être proposée en choix alternatif en utilisant la méthode d'authentification choice.

LL::NG peut utiliser une liste blanche ou noire pour filtrer les domaines OpenID autorisés.

Si OpenID est utilisé comme base d'utilisateurs, les attributs sont demandés en utilisant l'extension SREG d'OpenID.

Configuration

Dans le manager, aller dans Paramètres généraux > Modules d'authentification et choisir <a2>OpenID</a2> pour les modules authentification, utilisateurs et/ou mots-de-passe.

Ensuite, aller dans les paramètres OpenID :

  • Niveau d'authentification : niveau d'authentification accordé à ce module.
  • Secret token : utilisé pour vérifier l'integrité des réponses OpenID.
  • Domaines autorisés :
    • Type de liste : choisir liste blanche pour définir la liste exhaustive des domaines autorisés ou liste noire pour lister les domaines interdits
    • Liste : liste des domaines (séparés par des virgules)

Pour configurer les attributs à récupérer, éditer les Variables exportées et definir les attributs :

  • Clef : clef de session interne, peut être prefixé par ! pour exiger ces attributs
  • Valeur : noms d'attributs SREG :
    • fullname
    • nickname
    • language
    • postcode
    • timezone
    • country
    • gender
    • email
    • dob

Voir aussi la configuration des variables exportées.
